## 性能基准

### 标准性能指标

在默认配置下（2秒延迟，50页）：

| 指标 | 数值 |
|------|------|
| 单页爬取时间 | 2-5秒 |
| 单网站完整爬取 | 5-10分钟 |
| 四网站完整爬取 | 20-40分钟 |
| 数据处理时间 | 5-10秒 |
| 导出时间 | 5-15秒 |
| 总耗时 | 25-50分钟 |

### 影响因素

1. **网络速度**: 网络延迟和带宽
2. **网站响应**: 目标网站服务器性能
3. **爬取页数**: 页数越多耗时越长
4. **请求延迟**: 延迟越大耗时越长
5. **并发数**: 并发数越高速度越快（但可能被封）
6. **数据量**: 数据越多处理时间越长

## 爬虫优化

### 1. 调整请求延迟

**保守策略（推荐）**:
```yaml
crawl_settings:
  delay: 2  # 2秒延迟，安全稳定
```

**激进策略（风险高）**:
```yaml
crawl_settings:
  delay: 0.5  # 0.5秒延迟，速度快但易被封
```

**建议**: 从2秒开始，根据实际情况调整

### 2. 减少爬取页数

```yaml
crawl_settings:
  max_pages: 20  # 从50页减少到20页
```

**优点**: 大幅减少爬取时间
**缺点**: 可能错过部分房源

### 3. 选择性启用网站

```yaml
websites:
  lianjia:
    enabled: true  # 数据质量高
  anjuke:
    enabled: true  # 数据量大
  wuba:
    enabled: false  # 个人房源多，质量参差不齐
  beike:
    enabled: false  # 与链家重复度高
```

### 4. 使用代理池

```python
from utils import ProxyPool

# 添加多个代理
proxies = [
    'http://proxy1:8080',
    'http://proxy2:8080',
    'http://proxy3:8080',
]

proxy_pool = ProxyPool(proxies)

# 在爬虫中使用
proxy = proxy_pool.get_proxy()
response = requests.get(url, proxies={'http': proxy})
```

**优点**:
- 分散请求来源
- 避免IP被封
- 提高并发能力

**缺点**:
- 需要购买代理服务
- 代理质量参差不齐

### 5. 智能重试策略

```python
from utils import RetryStrategy

strategy = RetryStrategy(
    max_retries=3,      # 最多重试3次
    base_delay=1.0,     # 基础延迟1秒
    max_delay=30.0      # 最大延迟30秒
)

# 指数退避 + 随机抖动
# 第1次重试: 1-2秒后
# 第2次重试: 2-4秒后
# 第3次重试: 4-8秒后
```

## 数据处理优化

### 1. 批量处理

```python
# 不推荐：逐条处理
for house in houses:
    process_house(house)

# 推荐：批量处理
df = pd.DataFrame(houses)
process_batch(df)
```

### 2. 使用向量化操作

```python
# 不推荐：循环处理
for idx, row in df.iterrows():
    df.loc[idx, '单价'] = row['总价'] / row['面积']

# 推荐：向量化操作
df['单价'] = df['总价'] / df['面积']
```

### 3. 数据类型优化

```python
# 优化前
df['价格'] = df['价格'].astype(float)  # 64位浮点数

# 优化后
df['价格'] = df['价格'].astype('float32')  # 32位浮点数，节省50%内存

# 分类数据
df['区域'] = df['区域'].astype('category')  # 大幅减少内存
```

### 4. 延迟加载

```python
# 不推荐：一次性加载所有数据
all_data = pd.read_excel('huge_file.xlsx')

# 推荐：分块加载
for chunk in pd.read_excel('huge_file.xlsx', chunksize=1000):
    process_chunk(chunk)
```

## 内存优化

### 1. 及时释放内存

```python
import gc

# 处理完大数据后
del large_dataframe
gc.collect()
```

### 2. 使用生成器

```python
# 不推荐：返回列表
def get_all_houses():
    houses = []
    for page in range(100):
        houses.extend(crawl_page(page))
    return houses

# 推荐：使用生成器
def get_all_houses():
    for page in range(100):
        yield from crawl_page(page)

# 使用
for house in get_all_houses():
    process_house(house)
```

### 3. 分批处理

```python
# 分批处理大数据
batch_size = 1000
for i in range(0, len(houses), batch_size):
    batch = houses[i:i+batch_size]
    process_batch(batch)
```

## 网络优化

### 1. 连接池

```python
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

# 创建session
session = requests.Session()

# 配置重试策略
retry = Retry(
    total=3,
    backoff_factor=1,
    status_forcelist=[500, 502, 503, 504]
)

# 配置连接池
adapter = HTTPAdapter(
    max_retries=retry,
    pool_connections=10,
    pool_maxsize=10
)

session.mount('http://', adapter)
session.mount('https://', adapter)

# 使用session
response = session.get(url)
```

### 2. 压缩传输

```python
headers = {
    'Accept-Encoding': 'gzip, deflate',
    'User-Agent': 'Mozilla/5.0 ...'
}

response = requests.get(url, headers=headers)
```

### 3. 超时设置

```python
# 推荐的超时设置
response = requests.get(
    url,
    timeout=(3.05, 30)  # (连接超时, 读取超时)
)
```

## 并发优化

### 1. 多线程爬取

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
from utils import RateLimiter

def crawl_page(url, limiter):
    limiter.wait()
    return requests.get(url).text

urls = [f'http://example.com/page{i}' for i in range(100)]
limiter = RateLimiter(requests_per_second=5.0)

with ThreadPoolExecutor(max_workers=10) as executor:
    futures = {executor.submit(crawl_page, url, limiter): url for url in urls}

    for future in as_completed(futures):
        url = futures[future]
        try:
            result = future.result()
            process(result)
        except Exception as e:
            print(f"Error crawling {url}: {e}")
```

**线程数建议**:
- CPU密集型: 线程数 = CPU核心数
- IO密集型: 线程数 = CPU核心数 × 2-4

### 2. 异步爬取（推荐）

```python
import asyncio
import aiohttp
from utils import RateLimiter

async def crawl_page(session, url, limiter):
    limiter.wait()
    async with session.get(url) as response:
        return await response.text()

async def crawl_all(urls):
    limiter = RateLimiter(requests_per_second=10.0)

    async with aiohttp.ClientSession() as session:
        tasks = [crawl_page(session, url, limiter) for url in urls]
        results = await asyncio.gather(*tasks, return_exceptions=True)

    return results

# 运行
urls = [f'http://example.com/page{i}' for i in range(100)]
results = asyncio.run(crawl_all(urls))
```

**异步优势**:
- 单线程，避免GIL限制
- 高效的IO等待
- 可处理大量并发

### 3. 进程池（CPU密集型）

```python
from multiprocessing import Pool

def process_data(data):
    # CPU密集型任务
    return heavy_computation(data)

with Pool(processes=4) as pool:
    results = pool.map(process_data, data_list)
```

## 监控与调试

### 1. 性能监控

```python
import time
from contextlib import contextmanager

@contextmanager
def timer(name):
    start = time.time()
    yield
    elapsed = time.time() - start
    print(f"[{name}] 耗时: {elapsed:.2f}秒")

# 使用
with timer("爬取链家"):
    houses = spider.get_house_list("吉阳区", 1)
```

### 2. 内存监控

```python
import psutil
import os

def print_memory_usage():
    process = psutil.Process(os.getpid())
    mem = process.memory_info().rss / 1024 / 1024
    print(f"内存使用: {mem:.2f} MB")

# 定期检查
print_memory_usage()
```

## 优化策略对比

### 策略1：安全稳定（推荐新手）

```yaml
crawl_settings:
  max_pages: 30
  delay: 2
  timeout: 30
  retry_times: 3

websites:
  lianjia: {enabled: true}
  anjuke: {enabled: true}
```

**特点**:
- ✅ 稳定可靠
- ✅ 不易被封
- ❌ 速度较慢
- **预计耗时**: 30-40分钟

### 策略2：快速爬取（有风险）

```yaml
crawl_settings:
  max_pages: 20
  delay: 1
  timeout: 20
  retry_times: 2

websites:
  lianjia: {enabled: true}
  anjuke: {enabled: true}
```

**特点**:
- ✅ 速度快
- ❌ 可能被封
- ❌ 数据可能不完整
- **预计耗时**: 15-20分钟

### 策略3：并发爬取（高级用户）

```python
# 使用多线程
with ThreadPoolExecutor(max_workers=5) as executor:
    # 并发爬取多个网站
    pass
```

**特点**:
- ✅ 速度最快
- ✅ 效率高
- ❌ 需要代理池
- ❌ 实现复杂
- **预计耗时**: 10-15分钟

## 最佳实践

### 1. 渐进式优化

```
第一步：使用默认配置，确保功能正常
第二步：根据需求调整页数和延迟
第三步：选择性启用网站
第四步：使用代理池（如需要）
第五步：尝试并发爬取（高级）
```

### 2. 监控与调整

```python
# 定期监控性能
with timer("爬取任务"):
    result = engine.run()

# 根据结果调整配置
if elapsed > 3600:  # 超过1小时
    config.update_crawl_settings(max_pages=20)
```

### 3. 错误处理

```python
# 完善的错误处理
try:
    result = engine.run()
except NetworkError:
    logger.error("网络错误，请检查网络连接")
    # 重试或使用代理
except TimeoutError:
    logger.error("请求超时，增加超时时间")
    config.update_crawl_settings(timeout=60)
except Exception as e:
    logger.error(f"未知错误: {e}")
    # 保存已爬取的数据
    save_partial_data()
```

### 4. 资源管理

```python
# 及时释放资源
def crawl_with_cleanup():
    try:
        engine = HouseCrawlerEngine()
        result = engine.run()
        return result
    finally:
        # 清理资源
        del engine
        gc.collect()
```

## 常见问题

### Q1: 爬取速度太慢怎么办？

**A**:
1. 减少爬取页数
2. 减少请求延迟（注意风险）
3. 只启用必要的网站
4. 使用并发爬取

### Q2: 内存占用过高怎么办？

**A**:
1. 分批处理数据
2. 及时释放不需要的变量
3. 优化数据类型
4. 使用生成器

### Q3: 经常超时怎么办？

**A**:
1. 增加超时时间
2. 使用代理池
3. 添加重试机制
4. 检查网络连接

### Q4: 如何避免被封？

**A**:
1. 设置合理的延迟（≥2秒）
2. 使用代理池轮换IP
3. 模拟真实用户行为
4. 设置随机User-Agent
5. 遵守robots.txt
